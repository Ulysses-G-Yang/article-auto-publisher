# ArticleOps v0.4.5 草稿证据稳定性正式版

## 版本定位

v0.4.5 重点解决“平台已经保存草稿，但系统因为证据不稳定而显示失败或无法确认”的问题。
本次发行整理以
`a49293cfc3e949f31a84a6e022c4e978d8128586` 为功能代码基线；该 SHA 不是最终交付
SHA。最终发行还会包含发行文档和打包收口，客户应以压缩包内
`RELEASE_MANIFEST.txt` 或 `UPGRADE_MANIFEST.json` 记录的 40 位 `source_commit`
为准。

本版本仍以“保存平台草稿”为业务边界，不授权公开发布，也不会因为结果不确定而自动
再次保存。

## 业务人员能看到的变化

- **草稿绑定更稳定**：系统优先记录平台草稿卡片或编辑器的稳定 ID，避免仅凭标题、列表
  位置或临时地址判断。再次核验时会确认是同一个草稿实体，降低串稿和假失败风险。
- **支持只读核验现有草稿**：投递结果不明确时，可只读打开草稿箱核对标题、稳定 ID 和
  可见结构；核验过程不点击保存、发布或删除，也不自动登录。
- **已证实存在的草稿可收敛为可用结果**：若只读证据唯一指向本次草稿，系统可将结果
  收敛为 `DRAFT_SAVED_WITH_WARNINGS`，页面显示“草稿已保存（需核对）”。这表示草稿实体
  已找到，但仍建议业务人员复核正文、图片等内容，不代表已经公开发布。
- **不确定结果保持克制**：证据不足时继续返回 `RESULT_UNKNOWN`。系统不会自动重试，
  以免平台已经保存成功却被重复提交；应先人工查看草稿箱或使用只读核验。
- **操作状态中文化**：工作台、任务页和账号页使用统一的中文业务状态，减少英文状态码
  对日常操作的干扰。
- **登录后账号列表及时刷新**：交互式登录完成后，账号可用状态会重新加载，减少必须手动
  刷新页面才能选择账号的情况。
- **知乎修复**：优先使用规范编辑地址，并将自动保存结果绑定到稳定草稿卡片 ID，降低地址
  跳转或草稿列表变化造成的误判。
- **小黑盒修复**：草稿保存和后续核验绑定稳定编辑器 ID，减少同名草稿或编辑地址变化造成
  的错配。

## 仍然有效的限制

- 小红书的登录与账号管理可以继续使用，但云端草稿实体证据尚未完成闭环，自动草稿投递
  继续关闭。不得把本机编辑器内容、旧 Profile 中可见卡片或单次页面结果当作云端保存成功。
- `PUBLISH_AFTER_DRAFT=false` 和公开发布权限默认保持关闭。草稿授权不等于公开发布授权。
- MCP 默认关闭草稿写入能力。启用前必须由部署方通过外部环境变量设置独立内部令牌、
  Host 白名单、文件服务 Host 白名单和明确的账号 ID 白名单；账号白名单不得使用 `*`。
- 全新安装的默认账号白名单是无法命中真实账号的全零 UUID，仅用于让服务以拒绝真实账号
  的状态安全启动；完成登录和审批后必须替换为明确获准的真实 `account_id`。
- MCP 只授予获准账号的草稿能力，不授予公开发布能力。MCP 返回结果不确定时同样不得
  自动重试。

## 交付文件

本版本生成两类 Windows 交付包，文件名中的 `<source-sha>` 是最终构建提交的完整 40 位
SHA：

- `ArticleOps-v0.4.5-<source-sha>.zip`：用于全新运行目录的完整包。
- `ArticleOps-v0.4.5-<source-sha>.zip.sha256`：完整包校验值。
- `ArticleOps-upgrade-v0.4.5-<source-sha>.zip`：用于已有 v0.4.4 业务电脑的原地升级包。
- `ArticleOps-upgrade-v0.4.5-<source-sha>.zip.sha256`：升级包校验值。

已有业务电脑不要用完整包覆盖旧目录，必须先备份 `data/`，再按
`UPGRADE_v0.4.5.md` 先执行 `ValidateOnly`，校验通过后才执行实际升级。

## 数据与配置边界

完整包和升级包都不携带客户的 `data/`、SQLite 数据库、Cookie、Chrome Profile、
上传内容、日志或生产密钥。原地升级会保留 `data/`、`uploads/`、`images/` 和本机
`data\production_env.ps1`；升级器另行备份被替换的程序文件，但这不能代替客户在升级前
对整个 `data/` 做独立备份。

`start_production_windows.ps1` 不生成、覆写或自动加载生产配置。启动前必须在当前
PowerShell 会话中 dot-source `data\production_env.ps1`，或由部署系统把同等环境变量
注入启动进程，然后再运行启动脚本。
