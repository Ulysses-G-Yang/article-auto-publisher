# 创作与投递工作台

## 单一入口

`/upload` 是内容创作和投递的唯一主入口。侧边栏不再同时显示
“创建文章”和“内容投递”。兼容路由 `/delivery/new` 重定向至
`/upload`，并保留 `draft_id`。

## 三段主流程

1. 内容：新建空白草稿、导入 DOCX、继续系统草稿，或将只读历史
   文章复制为新草稿。
2. 投递目标：添加多个“平台 + 账号 + 平台草稿/公开发布”。
3. 核对执行：先冻结一个不可变内容版本，再为每个目标创建独立
   执行单。

“检查并继续”始终可点击。条件不足时，页面列出缺失项并将焦点
移到第一个需要处理的控件。

## 保存与冲突

- 每次标题或块编辑都立即写入 IndexedDB 恢复副本。
- 停止输入约 1 秒后，使用当前 `revision` PATCH 服务端。
- 顶部持续显示“本地已保存 / 正在同步 / 已同步 / 同步失败”。
- `409 DRAFT_REVISION_CONFLICT` 不会静默覆盖；用户可“采用服务端版本”
  或“将本地内容另存为副本”。

## 图文块

文字块和图片块共用一个有序列表。桌面端可拖动，同时保留“上移”
和“下移”按钮，作为键盘和移动端替代。图片只使用后端返回的
`asset_url`，不向 DOM 暴露本机路径。

## v2 Word 富文档预览

DOCX 导入返回 `content_schema_version=2` 时，正文使用 canonical
`document` 做只读保真预览。预览通过 DOM 节点构造文本、标题、列表、表格、
文字格式、HTTP(S) 链接和受控图片；用户文本、链接和图注不会拼接进
`innerHTML`，图片地址只允许 `/api/content-assets/{asset_id}`。

`title_block_id` 对应的标题块不在正文中重复显示，标题仍由独立标题输入框
维护。列表和表格中的嵌套块也会参与段落与图片统计。无法识别的节点只显示
安全占位，不执行未知内容。

这是当前阶段的保真预览，不冒充完整富文本编辑器。v2 正文编辑、粘贴、拖拽、
清空和插图入口会明确保持只读；需要替换正文时重新导入 DOCX。v1 草稿继续
使用原有可编辑图文块行为。

## 封面策略

封面只从当前正文的受控图片中选择，支持“不设置封面”“自动使用正文首图”
和“指定图片”。v2 会递归检查 canonical 文档中的段落、标题、列表和表格，
并排除 `title_block_id`；v1 则读取现有图片块。缩略图通过受控 asset URL
渲染，不展示本机路径。

带图片的 DOCX v2 导入完成后，系统只在该次导入流程中提示并自动选择正文首图。
用户改为“无封面”或指定其他图片后，选择会随草稿和本地恢复副本保存，普通重开
不会再次覆盖用户选择。`NONE` 与 `FIRST_BODY_IMAGE` 请求不会携带
`asset_id`，只有 `EXPLICIT` 才会发送明确的图片资产引用。

## 格式能力阻断

投递计划中的 `FORMAT_REVIEW_REQUIRED`、`CONTENT_FORMAT_UNSUPPORTED` 和
`PLATFORM_FORMAT_CAPABILITIES_UNDECLARED` 会显示中文原因和警示样式。格式阻断
目标不计入平台草稿批量确认，也不会创建执行单；混合计划只把可执行目标交给
执行接口。若全部目标被阻断，执行按钮禁用并明确说明原因。

## 账号与安全门

- 初始不请求账号；选定平台后才加载真实平台昵称。
- 系统不自动选账号，仅 `VALID` 账号进入可选列表。
- “保持登录态”是独立会话持久化策略，不当作登录状态。
- 平台草稿目标使用一次批量摘要确认。
- 公开发布目标在后端返回一次性令牌后逐条弹出高风险确认。
- 页面不依赖兼容端点 `/api/delivery-operations`。

## 执行状态与人工核对

- `CREATING` 显示“正在创建执行单”，属于短暂中间态，页面只轮询状态，
  不重复提交计划。
- `PARTIAL_FAIL` 显示“部分失败”，提示用户核对图片完整性和平台结果；
  已成功目标不受影响。
- `RESULT_UNKNOWN` 显示“结果未知，需人工核对”，并明确要求先到对应平台
  检查。系统不会自动重试，也不提供公开发布自动重试按钮，避免重复发布。
- `RESULT_UNKNOWN` 与 `PARTIAL_FAIL` 使用警告色徽章，`CREATING` 使用信息色徽章；
  颜色之外仍保留完整中文状态文案。

## 响应式与可访问性

上游 CoreUI 布局、表单、Modal 和 SimpleBar 负责基础结构。ArticleOps
业务扩展在 1280px 下将右侧摅要改为横向区域，在 768px 下将复杂操作
竖向排列，在 390px 宽度保留完整主操作。动态图文块均有明确 label/
`aria-label`，错误区域使用 `role="alert"`，保存状态使用 `aria-live` 通知。
