## 根因与修复

原适配器把文字和图片分批写入，图片路径还可能回退到第一张图；同时把 heading
降级为普通文本，并依赖容易失效的编辑器定位与页面正文子串判断。这些隐式契约在
真实 Draft.js 编辑器重绘、水合和空白规范化后会造成乱序、误判或假成功。

本轮修复为：

1. 按冻结 ContentVersion 的原始块顺序交错写入 text、heading 和 image。
2. 图片只能按冻结资产精确映射，缺失或歧义时 fail closed，禁止首图 fallback。
3. Word H2 使用平台真实工具栏写入；未验证的标题层级继续拒绝执行。
4. 使用 Draft.js 可观察的键盘光标移动，不再用只改变 DOM Range、却不同步
   SelectionState 的伪光标。
5. 图片弹层每次上传后必须关闭，并重新读取当前编辑器 DOM；每一步校验已写前缀，
   最终严格比较完整有序 token。
6. 保存后从草稿 API 取得完整标题的唯一草稿实体，只接受安全草稿 ID；重新打开精确
   `/p/{id}/edit` 地址并轮询等待异步水合，然后再次校验完整标题与图文结构。
7. 保存动作之后出现任何不确定性统一返回 `DRAFT_RESULT_UNKNOWN`，禁止自动重放。
