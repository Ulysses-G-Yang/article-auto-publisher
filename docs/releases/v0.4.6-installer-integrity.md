# ArticleOps v0.4.6 正式版

## 版本定位

v0.4.6 保留 v0.4.5 的草稿证据稳定性功能，并修正 Windows 完整安装包的两个交付问题。
平台适配器、草稿业务逻辑、账号数据和公开发布边界均未改变。

## 本次修正

- 完整包的环境检查只验证生产运行模块，不再把开发测试依赖 `pytest` 当作运行必需项。
- 无 `.git` 的完整包会从 `RELEASE_MANIFEST.txt` 读取唯一的 40 位 `source_commit`，并真正
  校验 `setup_windows.ps1 -ExpectedCommit`。
- 构建器会同时核对 `pyproject.toml`、`src/article_mvp/__init__.py` 和构建参数中的版本，
  防止包名与运行代码版本不一致。
- v0.4.5 未交付给业务人员，v0.4.6 是本轮唯一应安装或升级的版本。

## 草稿功能基线

- 平台草稿优先绑定稳定草稿 ID，并支持只读核验。
- 唯一证据确认草稿存在但内容仍需复核时，页面显示“草稿已保存（需核对）”。
- 证据不足时返回结果未知，不自动重试，避免重复草稿。
- 小红书云端草稿证据尚未闭环，自动草稿投递继续关闭。
- `PUBLISH_AFTER_DRAFT=false`，公开发布权限默认关闭。

## 交付文件

文件名中的 `<source-sha>` 是最终构建提交的完整 40 位 SHA：

- `ArticleOps-v0.4.6-<source-sha>.zip`：全新 Windows 运行目录使用。
- `ArticleOps-v0.4.6-<source-sha>.zip.sha256`：完整包 SHA-256。
- `ArticleOps-upgrade-v0.4.6-<source-sha>.zip`：已有业务电脑原地升级使用。
- `ArticleOps-upgrade-v0.4.6-<source-sha>.zip.sha256`：升级包 SHA-256。

已有业务电脑必须先备份整个 `data/`，再按 `UPGRADE_v0.4.6.md` 先执行 `ValidateOnly`。
完整包和升级包均不携带客户数据库、Cookie、Chrome Profile、上传内容、日志或生产密钥。
