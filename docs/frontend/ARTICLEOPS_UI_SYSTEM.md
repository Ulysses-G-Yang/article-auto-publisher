# ArticleOps UI v2 设计与交互规范

## 目标与边界

本轮统一 `/`、`/upload`、`/accounts`、`/task/*` 与 `/data-center/` 的视觉和操作方式，保持所有既有路由、API、表单字段、投递规则和平台适配器不变。

`sidebar_permissions` 只用于服务端渲染时隐藏无权查看的导航入口，属于界面投影，不是安全鉴权。后端路由和 API 必须继续独立校验权限。

外部 AI 分析接口不在本轮实现。待产品给出详细契约后，再确定发送的 Word 内容、平台选项、审计字段、超时和降级行为。

## 设计令牌

唯一令牌源为 `web/static/css/design-tokens.css`。业务页面只能优先引用令牌，不应自行新增近似颜色、圆角或阴影。

| 类别 | 约定 |
| --- | --- |
| 品牌色 | 清晰的蓝色阶，主操作使用 `--ao-blue-600` |
| 中性色 | Slate 色阶承担正文、次要文字、边框和背景 |
| 状态色 | 成功、警告、失败、信息均同时显示颜色与文字 |
| 字体 | 系统无衬线字体栈，正文保持可读行高 |
| 间距 | 4 / 8 / 12 / 16 / 24 / 32 / 40px |
| 圆角 | 控件、卡片、浮层分别使用统一语义令牌 |
| 焦点 | 2px 品牌色焦点环并保留可见间距 |
| 主题 | 浅色与深色共享同一语义令牌 |

## 侧边栏

- 桌面默认宽度 248px，可拖动或用方向键在 216–320px 间调整。
- 支持收成 80px 图标轨道，保持当前页面入口可辨识。
- 导航按“工作台 / 管理”分组，允许独立折叠；包含当前页面的分组始终展开。
- 宽度、折叠状态、分组状态和主题均保存在本地偏好中，主站与数据中心使用同一组键。
- 移动端改为 288px 抽屉；点击遮罩或按 `Esc` 关闭，并把焦点归还给菜单按钮。
- 调宽分隔条支持鼠标、触控和键盘，移动端不显示。

## 组件与操作规则

- 每个页面只保留一个视觉最强的主操作；返回、刷新和取消使用次级样式。
- 按钮、输入框、导航和可点击卡片的操作高度不低于 44px。
- 整张账号卡、平台卡等高频目标应可点击，不把操作限制在小图标或文字上。
- 禁用操作必须给出原因；异步操作同时提供加载、空、成功和失败状态。
- 状态不能只依赖颜色，必须配套中文文字；危险操作保持二次确认。
- 表格在窄屏只让容器横向滚动，页面本身不得产生横向溢出。
- 尊重 `prefers-reduced-motion`，不强制播放非必要动效。

## 页面结构

### 发布概览

按“运行状态 → 最近投递 → 历史任务”组织。新建内容是唯一主操作，旧任务和日志继续沿用现有数据契约。

### 创作与投递

使用“内容 → 投递目标 → 核对执行”的连续步骤。Word 导入入口前置；编辑区保持主要宽度，辅助栏在中等屏幕提前换行，避免编辑器被挤窄。账号不自动选择。

### 账号管理

流程固定为“选择平台 → 查看状态 → 操作账号”。登录、验证、归档和清除登录态保持原有 API 与安全确认；活动日志仍按账号隔离。

### 数据中心

保留运营总览 / 单篇文章模式、GridStack、模块显隐和独立错误状态。指标卡使用低饱和表面，不用高饱和渐变抢占信息层级。侧栏能力与主站一致。

## 响应式与验收

固定检查 `320 / 390 / 768 / 1024 / 1440px`：

- 页面无横向溢出，移动侧栏完整可见。
- 侧栏折叠、分组、调宽和主题刷新后仍保留。
- 键盘顺序、焦点环和 `Esc` 行为正确。
- 主要点击目标达到 44px。
- 浅色与深色下正文、边框和状态文字均可辨识，满足 WCAG AA 的常规文本对比目标。
- 页面初始化不因侧栏功能发起额外 API 请求。

## 后续 AI 接口预留

前端只预留未来入口的产品位置，不添加假接口、假结果或硬编码建议。详细计划至少需要冻结：请求内容、平台选项模型、返回结构、人工确认点、权限、日志脱敏、超时、失败降级与成本上限。
