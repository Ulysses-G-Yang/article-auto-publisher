# 登录检查与操作节奏

本批实现适用于现有平台适配器，不接入新平台、插件或 AI。它改善错误分类、
重复导航与编辑器操作节奏，不承诺避免平台风控，也不会自动处理验证码。

## 登录检查

- `check_login()` 返回 false 而没有明确失效证据时，报告 `SESSION_CHECK_FAILED`
  或平台原有稳定检查错误码，不要求重新扫码。
- 身份接口明确返回未认证、出现实际登录页面或可见密码表单时，才报告
  `LOGIN_REQUIRED`。Cookie 缺失本身不证明会话过期；SMZDM 全新、没有任何站点
  Cookie 的候选仍按其既有原生人工登录路径处理。
- 可见安全验证报告 `CHALLENGE`，频率限制报告 `RATE_LIMITED`，停止当前动作。
  检查超时、接口错误与安全验证不会因允许交互式登录而自动转入 login()。
- 手动账号验证失败的当前状态显示为 ERROR，保留最后一次成功验证时间作为历史；
  明确失效才显示 LOGIN_REQUIRED。投递前任何检查或身份绑定失败都禁止发布。

## 一次任务内的会话

DeliveryService 在原账号 Profile 租约内初始化一次浏览器并核对稳定账号身份。
成功后只给紧接着的 Base.publish 一次复用机会，避免第二次 check_login 导航。
复用结果绑定同一浏览器 Context、Page、页面 URL、Profile、asyncio task，最长
30 秒，消费后立即失效；换页面、换任务、重启或关闭浏览器均不能沿用。
不复用前端旧 VALID 状态，也不跨执行单缓存身份。

通用启动器继续使用系统 Chrome 与原独立用户资料目录。删除 navigator 属性伪装，
不再关闭站点隔离；保留原网络出口参数，本批不改变代理路径。明确的目录占用仍拒绝；没有占用证据的启动
失败报告 BROWSER_START_FAILED，不再冒充 PROFILE_IN_USE。头条继续保留此前验收过的
原生 Chrome + CDP 路线，没有把所有平台切换到 CDP。

操作结束正常关闭本次浏览器。“保持登录”保留资料目录中的持久状态，不表示浏览器
常驻或会话永不过期。本批没有修改用户 Cookie、Profile 或任何生产运行配置。

## 统一动作节奏

现有平台的原生点击、键盘控制、上传、选择、导航和已知脚本写操作统一经过
`ActionPacer`。原平台继续负责唯一控件、页面就绪、完整图文回读及单次保存/发布证据。
控制器串行执行动作，失败向上传递，不自行重试或回退重写内容。
响应与文件选择器的显式等待预算增加动作间隔，避免等待窗口先被程序自身的停顿耗尽。

| 项目 | 默认值 | 配置允许范围 |
| --- | --- | --- |
| 正文逐字间隔 | 随机 0.167–0.25 秒 | 字速上限每秒 1–8 字，单字间隔随机为其倒数的 1–1.5 倍 |
| 动作完成到下一动作开始 | 每步重新抽取 5–10 秒，首次动作也等待 | 最小值至少 5 秒、最大值至多 10 秒，两者不能相等 |
| 正文段落停顿 | 随机 1.2–2.4 秒 | 基准 1–5 秒，实际随机为其 1–2 倍 |

配置位于现有平台配置的 `action_pacing` 下，字段分别为
`characters_per_second`、`action_interval_min_seconds`、`action_interval_max_seconds`、
`paragraph_pause_seconds`。旧 `action_interval_seconds` 在校验后统一迁移为默认的
5–10 秒随机范围，不保留旧 0.5/1 秒快速路径，也不继续使用固定间隔。
未配置则使用上述默认值；布尔值、非有限数字和超出边界的配置会被拒绝。
已有平台图片等待、逐块回读与其他稳定等待仍然有效，实际速度可能更慢。
原生聚焦、滚动到控件以及脚本定位光标/追加空段也经过同一控制器；读取 DOM、
平台自身后台请求和一次输入内的每个字符不各自等待 5–10 秒。字间使用上表的小幅
随机停顿，不改正文、不插入随机错字。事件等待按最大 10 秒而非平均值预留预算。

标题和搜索框保留一次完整原生 fill，富文本标题保留一次完整 insert_text，
在此前预留与字数相应的时间，避免平台把逐字标题当成自动建稿依据。
ZOL 的特殊 TinyMCE 结构块按字数
预留间隔后原子插入，保留已验收的标题结构；普通正文使用逐字输入。
标题格式等短快捷序列保留一次原生连续按键调用，其按键延迟每次随机抽样，避免
改动既有编辑器控制路径；普通正文仍逐字重新抽样。

这些间隔是可靠性参数，不是平台认可的安全阈值。暂停平台的代码只参加离线回归，
不因此恢复其登录、刷新、保存或发布。

## ZOL 认证

停用 `.zol.com` 到 `.zol.com.cn` 的认证 Cookie 复制。旧私有兼容钩子仅返回 0；
即使旧调用方传入 allow_cookie_bridge=true，也不会读出并复制认证数据。
复用现有创作者中心原生登录入口，后端身份/会话未确认则停止，要求人工核对原生
登录流程。现有机器上此前已经存在的 Cookie 不清除、不迁移。

## 验证边界

新增虚拟时钟测试验证输入速率、动作串行化、部分输入中断不重输、配置边界；
真实隔离 Chrome 验证多行正文、Unicode 和可见认证 UI 分类。已有冻结内容到平台
适配器测试继续核对标题、标题层级、图片顺序和单次提交保护。
测试不打开真实账号，不把离线通过写成新启动配置已完成真实平台验收。

## 头条本地拦截与网络提示（2026-09-15）

此前原稿发布保护默认阻止所有 POST，仅允许严格绑定原稿的预览和公开提交。
本机记录与头条原生脚本证实：请求被主动取消也会进入网页的“网络错误”通用提示。
这与用户网络断开、平台业务拒绝及登录过期是不同状态。

本批仅为已观察到的原生会话协议、通知读取、资格查询、页面配置和后台上报增加
精确 HTTPS 主机、路径和 POST 方法例外，见 `platforms/toutiao_request_policy.py`。
未知接口、相似域名、路径后缀、其他端口、带凭据 URL 不获得例外。原生读取放行，
文章保存/发布仍须核验账号、原稿、完整图文及选项，预览与公开分别最多一次；新建、
删除、立即发表等写接口即使用 GET 也禁止。

图片导入 `/spice/image` 是上传类操作，不能当作图片读取放行。纠错开关接口的
读取/写入参数还没有足够证据，仍拒绝。原稿如依赖这些操作，下一次内容检查明确
停止为 `TOUTIAO_LOCAL_REQUEST_BLOCKED`；不是隐藏提示、伪造成功或继续点击。
正常保存前的后台自动保存与重复提交仍被取消，页面对此仍可能弹提示，不能宣称
所有“网络错误”都已消失。进一步去掉重复自动保存需协调原生编辑流程，而非开放
额外写入。本批没有重新打开真实平台或重发成功文章。

进程日志与有界本地事件分别记录 LOCAL_REQUEST_BLOCKED、BROWSER_REQUEST_FAILED、
PLATFORM_HTTP_ERROR、PLATFORM_BUSINESS_ERROR；不记录完整 URL、Cookie、请求正文或
平台返回的自由文本。浏览器失败事件并不等同于宽带故障，仍需按实际失败证据诊断。

## 持续保持会话：当前未实现，后续改动顺序

已经实现的是保留原 Profile、检查失败不冒充登录过期，以及同一任务内复用一次
身份检查。尚未实现跨任务复用常驻浏览器。`BasePlatform.cleanup()` 与头条专用
cleanup 仍关闭本次窗口，DeliveryService 无论 persist_login 开关如何都会调用
cleanup；该开关当前只决定是否保留持久认证状态，不能解释为“始终在线”。

后续应先在已有 AccountRuntime 内管理账号浏览器的所有权，再改现有账号服务和
DeliveryService 的获取/释放流程。具体顺序是：

1. 先让一个明确的运行进程持有同账号的浏览器及 Profile 独占租约；Web/MCP 复用
   同一所有者，其他进程不能绕开租约另起窗口，不把端口记录当作已验证身份。
2. 登录、身份核对与后续发布借用同一已验证系统 Chrome；每次使用前确认连接存活、
   Profile 归属、当前稳定账号身份，不复用跨任务的旧身份凭据。
3. 普通任务结束释放业务使用权。仅在保存/发布结果明确、编辑器无待写请求且已退出
   编辑页后，卸载本次任务的路由和监听器，清除任务计数与旧身份凭据，再进入可复用
   空闲状态；未知结果与验证码冻结该账号，禁止下一任务接管。
   用户关窗、主动退出或服务退出时完整释放浏览器与 Profile 租约。
4. 用临时 Profile 验证两次任务的浏览器进程相同、无重复登录、并发争用被拒绝、
   断开/未知状态不能被当作健康会话，再在用户下一次正常任务中验证原账号。

不能只删除 cleanup 的 close，也不应新增频繁刷新登录页的“心跳”来冒充保活。
浏览器保持打开仍不能保证平台永不使登录失效。此处是待实现流程，不属于本批已完成项。
