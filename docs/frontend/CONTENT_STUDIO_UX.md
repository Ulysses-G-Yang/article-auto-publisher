# 创作与投递工作台

## 单一入口

`/upload` 是内容创作和投递的唯一主入口。侧边栏不再同时显示
“创建文章”和“内容投递”。兼容路由 `/delivery/new` 重定向至
`/upload`，并保留 `draft_id`。

## 三段主流程

1. 内容：新建空白草稿、导入 DOCX、继续系统草稿，或将只读历史
   文章复制为新草稿。
2. 投递目标：添加多个“平台 + 账号 + 平台草稿/公开发布”。
3. 核对执行：先冻结一个不可变内容版本，再为每个目标创建独立
   执行单。

“检查并继续”始终可点击。条件不足时，页面列出缺失项并将焦点
移到第一个需要处理的控件。

## 保存与冲突

- 每次标题或块编辑都立即写入 IndexedDB 恢复副本。
- 停止输入约 1 秒后，使用当前 `revision` PATCH 服务端。
- 顶部持续显示“本地已保存 / 正在同步 / 已同步 / 同步失败”。
- `409 DRAFT_REVISION_CONFLICT` 不会静默覆盖；用户可“采用服务端版本”
  或“将本地内容另存为副本”。

## 图文块

文字块和图片块共用一个有序列表。桌面端可拖动，同时保留“上移”
和“下移”按钮，作为键盘和移动端替代。图片只使用后端返回的
`asset_url`，不向 DOM 暴露本机路径。

## 账号与安全门

- 初始不请求账号；选定平台后才加载真实平台昵称。
- 系统不自动选账号，仅 `VALID` 账号进入可选列表。
- “保持登录态”是独立会话持久化策略，不当作登录状态。
- 平台草稿目标使用一次批量摘要确认。
- 公开发布目标在后端返回一次性令牌后逐条弹出高风险确认。
- 页面不依赖兼容端点 `/api/delivery-operations`。

## 响应式与可访问性

上游 CoreUI 布局、表单、Modal 和 SimpleBar 负责基础结构。ArticleOps
业务扩展在 1280px 下将右侧摅要改为横向区域，在 768px 下将复杂操作
竖向排列，在 390px 宽度保留完整主操作。动态图文块均有明确 label/
`aria-label`，错误区域使用 `role="alert"`，保存状态使用 `aria-live` 通知。
