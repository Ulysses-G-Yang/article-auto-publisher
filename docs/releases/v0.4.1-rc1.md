# ArticleOps v0.4.1-rc1

## 候选范围

本候选版本聚焦 `/upload` 创作工作台和 Windows 可复现发布包。它不是正式
`v0.4.1` 发布，也不自动创建或推送正式版本 tag。

### `/upload` 行为

- 普通 `/upload` 永远打开内存中的空白工作台，不读取最近草稿，不自动选择
  `drafts[0]`，也不因为访问页面创建空数据库记录。
- 只有 `/upload?draft_id=<id>` 才恢复指定 ContentDraft；刷新同一 URL 保持该草稿。
- IndexedDB 只按显式 `draft_id` 读取；用户输入、插图或选择目标时，未持久化空白态才采用最小 lazy-create。
- 每次 DOCX 导入独立创建新的 ContentDraft，成功后将 URL 更新到新的 `draft_id`，Word 默认 `cover=NONE`。
- 历史草稿 modal 仅在用户点击时 GET 列表，展示标题、来源类型/文件名、创建/更新时间、状态和“继续编辑”。

### 投递目标

- 十个平台统一展示：小黑盒、ZOL、知乎、什么值得买、百家号、小红书可投递；
  微博、头条号、抖音仅账号管理；微信公众号即将接入。
- 平台未开启时模式按钮禁用；账号请求按平台隔离，只展示 `VALID` 账号，不自动选择账号。
- 没有可用账号的平台提供 `/accounts?platform=<id>` 入口。知乎保持可投递能力。
- 公开发布默认关闭；三步导航、错误聚焦、计划防重复和无自动封面保持有效。

## 构建与验证

从候选提交的完整 40 位 SHA 构建：

```powershell
.\scripts\build_release_windows.ps1 -CommitSha <commit-sha>
```

构建脚本使用 Git archive 和白名单，排除 `.git`、`data`、数据库、Cookie、
Profile、日志、tests、QA 截图、node_modules、`uv.lock` 和本机绝对路径，并为
ZIP 生成 SHA256 sidecar。部署步骤见
[`docs/deployment/PRODUCTION_WINDOWS.md`](../deployment/PRODUCTION_WINDOWS.md)。

代码验收命令：

```powershell
node --check web\static\js\content-studio.js
node --check web\static\js\account-sessions.js
$py = (Get-Command python).Source  # 必须指向 Python 3.12 环境
& $py -m pytest tests\frontend -q
& $py -m pytest -q
& $py -m ruff check tests\frontend\test_content_studio_browser.py tests\frontend\test_content_studio_contracts.py
git diff --check
```

浏览器回归必须使用隔离数据目录和独立端口，不执行登录、平台草稿、DeliveryPlan
执行、公开发布或删除。RC 生产冒烟只允许导入 Word 到本地 ContentDraft，并确认
没有创建或执行 DeliveryPlan。

## 已知边界

- 本候选不重新验收平台适配器，不改变六平台后端适配器。
- 本候选不承诺公开发布验收，也不执行真实账号副作用。
- 正式 tag `v0.4.1` 需在候选全部验收通过后由发布负责人单独创建；候选 tag
  `v0.4.1-rc1` 同样只在全部验收通过后创建并推送。
