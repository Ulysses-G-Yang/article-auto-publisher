# ArticleOps ClearOps 界面系统

## 本轮目标

这套规则用于统一旧页面、数据中心和任务详情的视觉与交互，不改变任何后端接口、路由、任务状态或账号操作。现有 CoreUI 运行时继续作为基础，业务样式集中在 `web/static/css/style.css` 与数据中心的 `dashboard.css`。

## 组件约定

- 所有页面共用 `base.html` 的侧栏、顶栏、跳过导航和服务状态；数据中心保持独立模板，但复用相同的结构和 token。
- 主要操作使用一个清晰的品牌按钮；刷新、返回等辅助操作使用幽灵按钮，不与主操作竞争。
- 按钮、输入框、可点击卡片的可操作面积至少 `44px`，键盘焦点使用 `2px` 品牌色外框并留 `2px` 间距。
- 状态使用文字和颜色双重表达：成功、进行中、失败、结果未知和待补充不可只靠颜色区分。
- 表格在窄屏保持可横向滚动，页面本身不产生横向溢出；空态必须说明下一步。
- 所有自动刷新均为只读刷新，不改变任务状态；组件卸载时清理计时器。

## 页面信息架构

### 发布概览

顶部展示队列状态和“新建内容”，下面按「任务概览 → 最近投递 → 历史任务」排列。最近投递只保留一个列表，避免同一数据出现两次。历史任务通过任务编号进入详情页。

### 任务详情

以「任务概览 → 文章预览 → 执行日志」为固定顺序。待选择话题和暂停任务在概览卡片内显示下一步操作；错误码和错误信息保留原文，便于定位。

### 数据中心

继续支持运营总览 / 单篇文章切换、GridStack 模块显隐和旧摘要独立加载。卡片使用低饱和分类色，真实数据和缺失数据仍由原 `dashboard.js` 逻辑决定。

## 兼容边界

本轮没有改动 `/api/tasks`、`/api/status`、`/api/delivery-operations`、任务恢复接口、数据中心接口，也没有改变 Jinja 变量、Alpine 组件名或 localStorage key。账号、创作与投递模块继续由各自页面脚本负责。

## 响应式与无障碍验收

目标宽度为 `320 / 390 / 768 / 1024 / 1280 / 1440px`。重点检查：侧栏移动端开关、页面无横向溢出、表格可滚动、按钮可触达、焦点可见、`prefers-reduced-motion` 生效，以及空态/错误态具备可读提示。
