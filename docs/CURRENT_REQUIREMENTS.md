# ArticleOps 当前需求与执行顺序

更新日期：2026-09-15。依据用户在原任务与当前任务中的明确要求整理；后续明确
暂停或取消的要求优先于早期方案。实际现场结果见 HANDOFF_CURRENT.md。

## 1. 产品目标：一键真实发布

最终流程为：导入指定 Word → 核对标题、正文、标题层级和图片顺序 → 选择平台与
绑定账号 → 冻结本次内容和发布选项 → 执行平台原生发布 → 展示可核验的真实结果。
最终支持多平台、多账号，但当前先逐个平台完成真实发布验收。

用户 2026-09-07 明确要求“一键自动发文章”，2026-09-09 又明确“这个工具只需要能
发布就行了”。因此，编辑器写入成功、测试通过或仅保存草稿，都不能代替真实发布完成。
平台仅接收提交时记录 SUBMITTED；有对应公开实体和内容证据后才记录 PUBLISHED。

已有账号会话、Word 内容版本、投递计划和执行单继续复用，不另建一套工作流程。
需要封面、社区、话题时使用本篇内容及平台实际候选，未知选择不盲填。

## 3. 已取消与后置需求

- 数据采集、数据看板属于用户的其他方案，不由本项目继续实现或恢复。
- 完整诊断包、脱敏诊断包已被用户取消，不列作后续交付待办；保留必要的运行阶段、
  错误码、最后成功步骤、可能发生的副作用和下一动作说明。
- AI API Key、平台建议、自动判断社区/话题属于后置需求。已有相关代码保持当前状态，
  现阶段不接入、启用、调用或继续建设 AI，不把正文发送给新增服务。
- 不安装新插件，不增加外部日志服务、Cookie 池或万能平台适配器。
- 不恢复 ZIP/安装包交付；业务侧从唯一长期分支 main 更新源码。

## 4. 真实操作边界

- 仅使用项目系统 Chrome 和原绑定账号 Profile，不用 Codex 内置浏览器打开平台，
  不复制登录状态、不清 Cookie、不替换账号。用户登录或身份验证需要本人操作。
- 发布前核对本次浏览器中的稳定账号身份，不能凭前端旧“已登录”状态继续。
- 输入与点击放慢，正文和图片处理后完整回读；降速和 CDP 不等于平台风控保证。
- 已有逐个平台真实发布授权继续按具体任务使用，不要求用户反复确认相同授权。
  验证码、账号不一致、结果未知或暂停平台不属于可以自行越过的边界。
- 不确定保存/发布是否成功时标记 RESULT_UNKNOWN 或相应未知状态，先只读核对，
  不用新执行单重试、不自动新建同稿。明确需要重试已发生副作用时再取得针对性授权。

## 5. 交付与协作要求

每批完成后更新 HANDOFF_CURRENT.md，提交本任务相关文件，通过 SSH 推送 main，
核对远端完整 40 位 SHA。原有无关修改、真实账号数据、Profile 和用户内容不进入提交。
服务启动必须核对入口与进程归属，使用本机原有配置，防止新代码仍由旧进程运行。

进度汇报先说明已完成什么、当前单个平台的阻碍和下一动作；区分代码完成、离线测试、
真实平台结果及服务是否生效。回复按用户指定的 ADHD 风格，短编号、每项一个动作，
需要用户扫码或人工验证时明确指出当下唯一需要做的事。

当前进度：五个平台已有本篇真实发布证据，暂停平台保持暂停。头条本轮复用了既有执行单、
原稿和原账号，完成一次预览保存与一次公开提交；原稿恢复阶段有本机辅助步骤，不能据此
宣称网页无人值守一键发布已完整验收。后续收口现有网页发布入口及结果展示时继续复用
现有内容/账号/执行单，不拿这五篇成功稿再次试发，不恢复已取消或暂停的需求。
