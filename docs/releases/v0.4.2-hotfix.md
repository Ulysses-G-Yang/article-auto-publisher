# ArticleOps v0.4.2 草稿投递热修复

## 交付范围

本版本修复真实平台草稿证据与页面结果展示，不开启公开发布：

- 什么值得买：允许同名草稿；按保存前后 `/edit/{draft_id}` 集合差锁定唯一新增
  草稿，只读取一次草稿箱页面并在同一 DOM 中等待，不再循环刷新或依赖标题唯一。
- 什么值得买：重开新增草稿，完整核对标题、正文、7 张图片及图文顺序后才返回
  `DRAFT_SAVED`。2026-08-21 已用用户指定 Word 完成真实验收。
- 小红书：已确认网页长文卡片属于隔离 Chrome Profile 本地状态，另一干净浏览器
  无法看到，最终页也没有可验证的云端“保存草稿”动作。本版本关闭小红书投递，
  保留账号管理，明确返回“网页端无云端草稿”，不再把“暂存离开”冒充成功。
- 投递结果：每个平台独立显示成功、失败、结果未知或需要登录；计划汇总明确显示
  “全部成功”“部分成功 / 部分失败”或“全部失败”，不会让已成功目标看起来仍在
  等待人工审核。
- Windows 交付脚本统一使用带 BOM 的 UTF-8，确保系统自带 Windows PowerShell 5.1
  能正确解析中文提示和脚本内容。

## 安全边界

- `PUBLISH_AFTER_DRAFT=false`、`ACCOUNT_SESSIONS_ALLOW_PUBLIC_PUBLISH=false`。
- 失败或结果未知后不自动重放平台副作用。
- 完整包和升级包均排除 `.git`、`data`、数据库、Cookie、Chrome Profile、Token、
  日志、测试、QA 截图、`node_modules` 与 `uv.lock`。
- 升级包只替换清单内程序文件，保留生产配置、账号、Profile、历史记录、上传内容
  和数据库；失败时从 `data\upgrade_backups` 的文件级备份回滚。

## 已知边界

- 小红书本版本不可投递，只能管理账号；除非平台提供经真实验证的云端草稿动作，
  不得重新打开投递开关。
- 封面仍是可选项；本版本验收重点为 Word 正文、7 张正文图片和顺序。
- 本版本不创建或推送正式 tag；交付身份以压缩包清单中的 40 位 `source_commit`
  和同名 `.sha256` 为准。
