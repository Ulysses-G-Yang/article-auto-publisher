# ArticleOps v0.4.0-draft-delivery

## 交付能力

- 导入一个 Word 文档，保留正文文本、二级标题和正文图片顺序。
- 使用不可变 ContentVersion 对多个平台账号创建草稿计划。
- 小黑盒、ZOL、知乎、什么值得买、百家号、小红书真实草稿闭环已通过。
- 每个账号使用独立持久 Profile；操作、状态和日志按账号及执行单隔离。
- 公开发布总开关默认关闭；本发布版验收只执行 `DRAFT`。

## 默认行为

- DOCX 有图片时仍默认 `cover=NONE`，正文首图不会被自动当成强制封面任务。
- 用户可在冻结计划前显式选择 `FIRST_BODY_IMAGE` 或 `EXPLICIT`，但只有具备
  平台真实证据的封面能力才应作为正式承诺。
- 草稿结果未知时禁止自动重试；先只读核对平台实体，再决定恢复或人工处理。

## 运行环境

- Windows。
- Python 3.12 环境：`article-publisher-py312`。
- 开发入口：`app.py`，默认 `127.0.0.1:5000`。
- 生产入口：`run_flask_production.py` + Waitress。
- 数据、Profile、Cookie、Token 和 `uv.lock` 均不属于发布提交。

## 已知边界

- 本版本不承诺六个平台公开发布已验收。
- 本版本不把封面作为 Word 草稿交付阻断项。
- 小红书采用平台长文排版工作流；ZOL 标题必须不超过 35 字。
- Cookie 池、跨账号共享 SDK、采集契约和定时调度不在本发布版本范围。
