# ArticleOps 前端结构与验收

## 页面结构

应用继续使用原 Flask 服务和 5000 端口。数据中心采用浅灰画布、浮动白色侧栏、白色分析面板和克制的蓝色强调；暗色模式仍完整保留。旧页面的 Jinja 变量和 Fetch 接口不变。

数据中心继续使用 CoreUI 与 GridStack。顶部摘要是可拖动、可隐藏、可恢复的 `summary` 模块，其余工作流、接口契约、文章映射和采集运行模块保持可访问。默认信息路径固定为：平台筛选 → 四组真实指标 → 平台文章分布与映射完整度 → 发布和采集明细。

## 视觉令牌与参考边界

- 画布：`#f3f5f9`
- 主文字：`#1f2937`
- 次要文字：`#6b7280`
- 主色：`#2563eb`
- 面板：白色、18px 圆角、细边框和轻阴影
- 桌面侧栏：可收起、可调宽；移动端改为抽屉

布局语言参考本机 `18000` 数据看板，但没有复制其内联样式、CDN 图表依赖和移动端缺陷。平台分布与映射环图由本地 CSS 和 DOM 渲染，不引入新的线上运行依赖，也不伪造不存在的时间序列。

## 组合展示边界

数据中心在浏览器展示层并行读取两个互不依赖的数据源：

- `GET /data-center/api/dashboard` 仅提供新数据模块的 `summary`、`contract`、`articles` 和 `runs`。
- `GET /api/legacy-summary` 仅提供旧发布系统的脱敏摘要与任务列表。

前端不要求任一响应包含另一边的数据，也不在接口之间传递状态。新看板成功而旧摘要失败时，指标与新模块正常显示，旧工作流区显示“旧发布摘要暂不可用”；旧摘要成功而新看板失败时，任务列表仍正常显示，新指标与新模块单独显示错误。两个数据源都失败时各自保留错误状态，不生成替代业务数据。

## 指标模式和卡片语义

顶部先提供平台范围，再提供两个指标模式：

- 运营总览：汇总所有真实文章最新快照。
- 单篇文章：默认选择排序后的最新文章，也可通过选择器切换。

两种模式固定使用四张卡：基础信息、流量表现、互动表现、传播与采集。平台筛选和指标模式分别保存在浏览器 `localStorage`；单篇文章的原始链接使用新标签页、安全 `rel` 属性和可访问名称。

## 可空字段处理

不存在或为 `null` 的指标显示“—”。没有快照时显示“尚未采集 / 暂无数据”，不会将缺失值转成 `0`。`created_at` 只用于文章排序的兼容退化和映射表记录，不显示为正式发布时间。数据新鲜度只由 `latest_metric.snapshot_time` 计算。

后端提供以下正式可空字段，前端继续防御性处理缺失或 `null`：

- `articles[].title`
- `articles[].published_at`
- `articles[].latest_metric.exposure_count`
- `articles[].latest_metric.share_count`

## 本地验收

1. 使用项目既有 Python 环境启动 Flask 服务，确认仍监听 `http://127.0.0.1:5000`。
2. 依次访问 `/`、`/upload`、`/accounts`、已有的 `/task/<id>` 与 `/data-center/`。
3. 在数据中心切换平台和“运营总览 / 单篇文章”，切换文章，刷新页面验证筛选与模式保留。
4. 进入编辑看板，拖动模块、隐藏模块、保存布局并恢复默认。
5. 在 1440、1024、390 像素宽度检查侧边栏、表格、卡片与表单；确认无横向页面溢出，键盘焦点清晰。
6. 打开浏览器控制台，确认没有前端错误。验收空状态时不要向数据库写入模拟业务数据，也不要触发上传或真实平台发布。
