# ArticleOps v0.4.4 Windows 升级交付包

## 交付目的

v0.4.4 是面向已有 v0.4.3 业务电脑的原地升级包。包名中的 `<source-sha>`
是构建所用最终提交的完整 40 位 SHA；`UPGRADE_MANIFEST.json` 和同名 `.sha256`
分别记录载荷清单与压缩包校验值。完整新装包仅用于隔离的新目录，不作为本轮客户升级
交付物。

运行内容沿用已推送的 0.4.3 集成提交（`771b4e23d9ad8d2a7dd291445e56d7038197589b`）的
已验代码，客户可见更新包括 Word 内容归一化、批量目标草稿流程、保存结果证据与警告展示，
以及 MCP 状态返回。v0.4.4 本轮只整理升级交付，不重新实测所有平台，也没有执行真实平台
草稿保存或公开发布。

## 升级边界

- 升级载荷只更新最终提交中的程序、前端、发布文档和必要运行依赖。
- 为兼容客户现有启动方式，载荷不覆盖 `setup_windows.ps1`、
  `start_production_windows.ps1`、`stop_production_windows.ps1` 和
  `production_env.example.ps1`；升级器继续调用客户目录内原有的停止/启动脚本。
- `data/`、数据库、上传图片、Cookie、Chrome Profile、生产环境配置和日志不进入包，
  也不会被升级器删除。旧程序按文件备份到 `data\upgrade_backups`。
- 代码默认关闭 `PUBLISH_AFTER_DRAFT`、公开发布和旧队列；本包不主动开启任何开关，沿用客户
  已启用的配置，不执行登录、草稿保存、发布或删除。

## 交付前验证

客户先核对 `.sha256` 与 `UPGRADE_MANIFEST.json` 的 `source_commit`，再对已有
v0.4.3 目录执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\apply_upgrade_windows.ps1 -TargetRoot $targetRoot -ValidateOnly
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\apply_upgrade_windows.ps1 -TargetRoot $targetRoot
```

只有校验通过后才执行第二行；详见包根目录的 `UPGRADE_v0.4.4.md`。其它版本、路径不明或
升级结果不确定时停止操作并人工核对，不自动重试。
